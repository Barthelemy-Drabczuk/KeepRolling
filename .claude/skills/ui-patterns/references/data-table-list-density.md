# Data Table / List Density

**Reach for it when:** structured rows of data need to be scanned
quickly and accurately — more than a handful of records, several
columns, or values that need to be compared across rows.

**Shape:** consistent row height and column alignment (numeric values
right-aligned, text left-aligned), a fixed or sticky header, and a
chosen density that trades off information-per-screen against
readability.

**Contract notation:**
```
**Pattern:** Data Table / List Density
**Density:** <compact | comfortable | spacious>
**Column alignment:** <e.g. numeric right-aligned, text left-aligned, dates right-aligned>
**Row affordances:** <hover highlight, sticky header, zebra striping — which apply>
```

**Don't reach for compact density** on values that need careful
reading (financial figures, medical values, anything error-prone at a
glance) just to fit more rows on screen — density is a real tradeoff
against readability, not a free win.
