# Visual Hierarchy

**Reach for it when:** a screen has more than one possible action and
users need to know, without reading every label, which one matters
most right now.

**Shape:** one action styled with the most visual weight (size, color,
contrast, position); everything else visually recedes in a deliberate
order — never more than one element competing for "most important."

**Contract notation:**
```
**Pattern:** Visual Hierarchy
**Primary:** <the one action that should draw the eye>
**Secondary / tertiary:** <other actions, and how each is visually deprioritized>
```

**Watch for its failure mode instead of skipping it:** if a screen
ends up with three buttons all styled as "primary," the hierarchy has
failed, not succeeded. There should always be exactly one loudest
element per view.
